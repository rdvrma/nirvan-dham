# Video course: decisions log

Each decision with its reason, in order. The order that started this work: a video-lesson player for the Nirvan Sutra course app, behind a feature flag, on a branch, with a preview build; autonomous, no questions.

## D-001 Where the work happens
- The session runs on a local Windows machine (not a cloud session). The branch is `video-course` (it already holds the fixture and the schema doc, commit b2c3729, up to date with origin). No separate session branch was created: the final PR is `video-course` -> `main`. `main` is never touched.
- Reason: the order says "PR for the video-course branch"; a second branch would only add a merge.

## D-002 Stack facts that shape the design (read from the repo, not assumed)
- Next.js 16.2.9 (App Router, `output: 'standalone'`, React 19, Tailwind 4 installed but the course pages use inline styles with `var(--font-hind|inter|cormorant)` and the dark/gold palette `#050e07` / `#d4a843` / ivory `rgba(245,237,216,1)`), Supabase via `@supabase/ssr`, deployed on Vercel. `AGENTS.md` warns that this Next.js has breaking changes: its docs in `node_modules/next/dist/docs/` were consulted before writing route code.
- No unit-test runner exists (only ad-hoc `test-pw*.js` Playwright scripts at the repo root). Vitest and `@playwright/test` are added as dev dependencies (both MIT/Apache-2.0).
- The course language codes are `hi`, `en`, `hl` (Hinglish); the site UI language is `hi | en` (`src/lib/i18n.ts`). The reading flow lives at `/course/[lang]/[chapter]` (server component, Supabase `user_progress.highest_chapter_unlocked`), protected by `middleware.ts` for every `/course/*` path except `/course`.

## D-003 Security headers and middleware (revised after the YouTube-first amendment, see D-005)
- `next.config.ts` has a strict CSP. YouTube needs nothing new: `script-src` already allows `https://www.youtube.com` and `https://www.youtube-nocookie.com`, `frame-src` allows both, `img-src` allows `https:`, `media-src` allows `blob:` and `https:`. The CSP is therefore NOT changed (a regression test pins it). No `VIDEO_BASE_URL`, no R2 host.
- `middleware.ts` runs the Guard Dog (rate limit per IP and path) on every request except some static extensions. The local preview source requests `.m4a`, `.vtt` and `.json` files under `/course-fixture/` (audio is fetched with range requests): the matcher gets one extra exclusion for the `course-fixture/` path prefix so the preview is not rate-limited. Nothing else in the matcher changes; no request that exists today is affected.

## D-005 Video sources: YouTube first, local proxy for the preview (amendment 3', 5', 6')
- A `VideoSource` interface hides where the pictures come from. Two implementations: `YouTubeSource` (IFrame Player API, `enablejsapi=1`, `rel=0`, `playsinline=1`, host `https://www.youtube-nocookie.com`, `hl` from the site language, YouTube's own captions off by default `cc_load_policy=0`, native controls ON) and `LocalSource` (the committed 540p MP4 proxy, hls.js when a manifest has an HLS playlist; a separate muted-video + `<audio>` pair so the audio language can be chosen independently). `LocalSource` is used by the preview and whenever the lesson config has no YouTube id for the chosen audio language. A CDN source can be added later for gated lessons without touching the player.
- Per chapter lesson config: `{ manifest, youtubeIds: { hi: null, en: null }, enabledLanguages: ["hi"] }`; ids are placeholders until the owner fills them. English stays hidden until `enabledLanguages` lists it (machine translation and machine voice, not reviewed).
- No R2 upload script and no `VIDEO_BASE_URL`: dropped by the amendment. Gated practice videos must never use unlisted YouTube (written into `hosting.md`).
- Pause points: poll `getCurrentTime` every 200 ms, pause at each manifest pause point (they sit in >= 1 s silences, so a late pause is harmless), seek-back guard against seeking past a locked pause point. The reflection panel opens BELOW the player; nothing is ever drawn over YouTube's controls, branding or related-video strip.
- Captions: a custom overlay from the word-timing JSON (VTT fallback), bottom-centre, fixed baseline, subtle scrim, `pointer-events: none`. A jitter meter compares predicted and polled time while playing at 1x; if the 95th percentile of the deviation is above 250 ms the overlay falls back to sentence-level highlighting and logs it. With the YouTube source, YouTube's control bar occupies the bottom ~48 px while it is shown, so the caption baseline is `max(8 % of the player height, 52 px)` to keep the captions clear of YouTube's controls (the order says ~8 % and never to cover YouTube UI; both are met by the max).
- Dependencies (all MIT or Apache-2.0, versions in `dependencies.md`): hls.js (Apache-2.0), zod (MIT), vitest, vite, @vitejs/plugin-react, vite-tsconfig-paths, jsdom, @testing-library/react and /dom (all MIT), @playwright/test (Apache-2.0). The YouTube IFrame API is a Google service used under YouTube's API terms, not a package. `vitest@3` and `vite@7` were chosen because vitest 5 wants `@types/node >= 22` and the repository pins `@types/node@20`; no existing dependency was changed.

## D-006 Lint and measurement
- The repository's `react-hooks` lint rules (React Compiler set) flagged four patterns in my first player version (ref written during render, three `setState` calls inside effects). Fixed in the player rather than silenced: the pause-stop ref is updated in an effect, the retry button sets the loading phase itself, the reflection panel relies on being keyed per pause point, and loaded caption cues are stored together with the track they belong to (so a language switch shows no cues instead of the old language's until the new file arrives). The rest of the repository carries 53 lint errors and 1615 warnings that exist on origin/main as well (identical numbers); they were left alone ("fix only what I broke").
- Bundle delta is measured by loading each route in a fresh browser and summing the decoded and gzip bytes of the scripts (`scripts/measure-js.mjs`), against a build of origin/main made in a separate worktree with the same dummy Supabase env. Reason: it measures what a visitor downloads, not just what the build emits (the build tool no longer prints per-route sizes).
